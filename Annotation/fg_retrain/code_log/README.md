# fg_retrain 代码修改日志规范

从 2026-09-03 起，`Annotation/fg_retrain` 内所有程序修改都必须在本目录留下独立日志。

## 记录范围

以下文件发生新增、修改、移动或删除时必须记录：

- `src/**/*.py`；
- `configs/**/*.json`；
- `scripts/**/*.sh`；
- `tests/**/*.py`；
- 与程序运行协议直接相关的说明文件。

纯实验输出文件不作为代码修改逐文件记录，但其运行命令和输出目录应记录在对应实验日志中。

## 文件命名

```text
YYYY-MM-DD_HHMM_<实验编号或主题>.md
```

例如：

```text
2026-09-03_1700_E1_LAUX_IMPLEMENTATION.md
```

同一次修改只建立一个日志；后续独立修改不得覆盖旧日志。

## 每条日志必须包含

1. 修改时间；
2. 修改目的；
3. 修改范围；
4. 修改文件及具体内容；
5. 是否影响旧实验；
6. 验证方法与结果；
7. 对应运行命令；
8. 输出位置；
9. 已知假设或限制。

## 兼容与复现原则

- 新实验以新增入口、配置和启动脚本为主，不覆盖旧实验；
- 共享模块发生变更时，必须说明对E0、E1及后续实验的影响；
- 若无法保证向后兼容，应建立新版本模块，而不是修改旧实验语义；
- 日志只允许新增或补充勘误，不删除历史记录；
- 验证失败也必须如实记录，不能只记录成功结果。
